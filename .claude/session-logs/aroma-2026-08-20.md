안 됨 — 권장 불가. 이유 3개:

**1. 수량 confound가 ablation의 목적 자체를 오염**
exp4v2 cap=2534. full은 2534장 학습, ablation arm은 2000장 학습. full−A1 델타가 "ROI selection 기여"인지 "534장(21%) 덜 학습한 효과"인지 분리 불가. ablation은 리뷰어(R1-3, R3-3) 대응용 — 방법론 공격면을 스스로 만드는 셈. "arm 간 총량 동수" parity는 exp4v2 설계의 명시 원칙(운영 노트 ②)이기도 함.

**2. 구성 confound도 추가됨**
cap > pool이면 subsample 아닌 전량 소비 — full은 ring-우선 2534/3000 선별 소비(fallback=0), 2000-pool arm은 fallback 포함 전량 소비. 수량 외에 표본 구성까지 달라짐.

# 3단계 파이프라인 ablation — 단계별 상세 해설

## 파이프라인 구조 재확인

AROMA 합성 1장 = 3개 의사결정 체인:

```
[1] crop 선택        어떤 real 결함 crop을 쓸까      → roi_selection (compatibility)
[2] clean image 선택  어떤 정상 이미지에 붙일까        → clean_bg_selection (k_fit fitness)
[3] 위치 선택         그 이미지 안 어디에 붙일까       → ring site resolution (SGM+hist∩)
```

leave-one-out: 한 단계만 random으로 바꾸고 나머지 둘은 유지. 각 arm의 mAP 하락 = 그 단계가 하던 일의 가치.

---

## A1 — [1] crop 선택 제거 (random crop + AROMA bg + AROMA site)

**원래 하는 일**: compatibility 샘플링 — 결함 crop의 텍스처 cluster가 배경과 맞는(ctx_prior 높은) crop을 우선 선발. severstal에서는 top-1000이 (cluster×cell) 소수 pair에 집중 (로컬 k200 실측: AROMA 2개 pair vs random 151개 pair, ctx_prior 0.183 vs 0.013).

**제거하면**: crop이 5개 cluster 전역에서 무작위로 뽑힘. 대신 [2][3]은 살아있음 — 무작위 crop이라도 그 crop에 맞는 배경을 찾아주고(k_fit), ring으로 자리를 잡아줌. 합성 로그가 증명: `ring=2919/3000` — site 체인이 random crop에도 정상 작동.

**결과**: mAP .3061 — **3 arm 중 최고, 즉 손실 최소.**

**왜**: copy-paste에서 crop은 어차피 real 결함 — 어떤 crop을 골라도 결함 신호 자체는 진짜다. 선택이 기여하는 건 "배경과의 궁합"인데, 그 궁합은 [2][3]가 사후에 다시 맞춰준다 — random crop을 줘도 clean_bg_selection이 그 crop 기준으로 배경을 재선발하므로 궁합 결손이 하류에서 복구됨. H1(재조합 무정보) 가설과 정합: severstal에서 crop 다양성/집중도 차이는 검출기 학습에 거의 무정보. 부수 효과로 A1의 crop 다양성(151 pair)이 오히려 표본 다양성을 늘렸을 가능성도 있음. precision .496(최고)이 [2][3] 보존의 증거 — 그럴듯한 자리에만 붙으니 FP 유발 표본이 적다.

## A2 — [2] clean image 선택 제거 (AROMA crop + random 배경 + 위치도 연쇄 붕괴)

# 위치선택(Stage 3) 강조를 위한 실험 설계

## 왜 현재 설계에서 신호가 약한가

A3의 약한 신호(−0.3pt)는 설계 결함이 아니라 **severstal의 성질**: 근균일 표면이라 이미지 내 위치 간 분산 < 이미지 간 분산. 배경이 이미 fitness 상위면 "어디에 붙여도 대충 맞는" 데이터셋. 위치선택의 가치는 **배경이 이질적일 때** 드러남 — 이걸 역이용하는 게 설계의 핵심.

## 설계 옵션 4가지 (비용 순)

### D1. 데이터셋 전환 — mtd 우선 (코드 무수정, 최강 신호 예상)

mtd는 5종 중 유일하게 **이미지 내 대형 void(타일 밖 검은 영역)** 보유 — 랜덤 위치는 void 위에 떨어지고 ring은 회피. severstal proxy에서도 random 위치의 void 노출이 66~110/400이었는데, mtd는 구조적으로 훨씬 심할 것. kolektor(정류자 구조 표면)가 2순위. **가설을 사전 등록**: "full−A3 격차는 배경 이질성에 비례한다 — severstal(균일) 최소, mtd(void 대형) 최대." 맞으면 위치선택 강조 + 데이터셋 적응성(data-driven 서사, R1-1)까지 동시 입증. severstal 약신호가 결함이 아니라 **예측된 패턴의 한 점**이 됨.

### D2. site-score 층화 arm (코드 무수정 추정, 가장 깨끗한 인과 분리)

현재 A3는 on/off 이분법. 대신 **연속 처치**로: A3의 random-위치 산출물 전체를 기존 재채점 스크립트(analyze_smoke_arms.py — 파이프라인 함수 재사용, 오차 2.5e-7 검증됨)로 site_score 매기고, **상위 절반 vs 하위 절반**으로 annotations.json을 쪼개 각각 exp4v2에 투입. 같은 crop·같은 배경·수량 동일, **위치 품질만 다름** — 연쇄 confound 완전 제거. 상위>하위가 나오면 "site score가 downstream 가치를 예측한다"는 스코어 자체의 타당성 입증 — R3-3(스코어링 입증) 대응에 직격.

### D3. dose-response — ring 등급화 (소규모 확인 필요)

best-ring / ring-pool 내 random / uniform random / **worst-ring(최하위 자리 고의 선택)** 4단계. 단조 하강 곡선이 나오면 on/off 델타보다 훨씬 강한 증거. 단 worst-site arm은 기존 플래그로 가능한지 미확인 — ring pool이 상위 16개만 방출한다면 코드 수정 필요 → "코드 무수정" 원칙 위반 가능. D2가 같은 논증을 무수정으로 하므로 D3는 D2 결과 부족할 때만.

### D4. 서사 보강 — paired 비교 (추가 실험 0)

A3는 full과 **(crop, 배경) 쌍이 동일**하고 위치만 다름 — 이미 paired 설계다. 활용:
- **paired figure**: 동일 (crop,bg)에서 ring 위치 vs random 위치 나란히 — void 위/경계 걸침 사례를 시각 대비. 논문 그림 1장으로 메커니즘 전달.
- **precision 서사**: A3 signature가 precision −4.9pt / recall +1.4pt — "위치선택 = FP 억제 장치"라는 기능적 정의. AROMA 전체의 정밀도-주도 개선 패턴과 일관.

## 권장 조합

**D1(mtd) + D2(층화) + D4(그림·서사)**. D1이 "언제 중요한가", D2가 "스코어가 진짜 측정하는가", D4가 "왜 그런가"를 각각 담당 — 셋 다 코드 무수정. 비용: D1 = mtd 합성 3 arm + GPU 9 run(단 mtd는 `--compile` 금지), D2 = 재채점 CPU + GPU 6 run(상/하위 × 3 seed), D4 = 0.

주의 1건: D1을 "신호 잘 나오는 셋 골라잡기"로 쓰면 안 됨 — severstal 약신호를 **함께** 보고하고 이질성-비례 가설의 검증으로 프레임해야 정직성 원칙 유지.

진행 방향 정해지면 (예: D1+D2 채택 여부, 실행 순서) 가이드에 반영하겠음.

## 식별 구조부터 정리 (가산 모형)

full이 없어도 산술이 성립하는 범위를 정확히 하자. `mAP(arm) = F − Σ(제거 단계 비용)`, c1=crop, c2=배경, c3=위치라 하면:

```
A1 = F − c1          A3 = F − c3          A2 = F − c2 − c3 (연쇄)
```

| 도출량 | 계산 | 값 | F 필요? |
|---|---|---|---|
| **c2 (배경 단독)** | A3 − A2 | +2.1pt | **불필요** ✅ |
| **c3 − c1 (위치−crop 차)** | A1 − A3 | +0.3pt | **불필요** ✅ |
| c1, c3 각각 | full 필요 | ? | 필요 ❌ |

**중요 정정**: dev_note 기여서열표는 c3 추정에 "A1 ≈ 준-full (c1≈0)" 가정을 썼는데, **c2 식별에는 그 가정이 아예 불필요**하다 — A3−A2 산술은 full 없이 성립. 가장 강한 주장(배경 기여 2.1pt)이 가장 약한 가정 위에 있음. 현재 문서 서술은 필요 이상으로 강한 가정을 걸어 논거를 스스로 약화시킨 상태.

## ✅ 타당한 주장 (가정 명시 조건부)

1. **"배경 선택 단독 기여 ≈ +2.1pt"** — 가산성 가정만 필요, proxy 가산성 실측(0.131→0.081→0.061)이 근거. 논리적으로 가장 견고.
2. **"위치 기여 ≥ crop 기여"** (c3−c1 = +0.3pt > 0) — 단 격차가 노이즈 경계라 "위치 ≳ crop" 이상 금지.
3. **순위 A1 > A3 > A2** — 기술적(descriptive) 진술로 유효.
4. **proxy↔downstream 방향 일치** — 삼각측량으로 유효하나 "3개 arm 순서 일치"는 통계가 아닌 정성적 corroboration임을 자인해야.

## ⚠️ 과장 위험 — 지금 문구 그대로 쓰면 걸리는 것

1. **"부호 3/3 seed 일치"** — 기술적으로 참이나 오도 위험. seed1의 3 arm 값: .3026 / .3008 / .3001 — **전체 스프레드 0.0025**, 사실상 동률. 순위는 seed 42·2가 만든 것. 정직 서술: "2/3 seed에서 명확한 격차, 1 seed는 근사 동률(부호는 일치)".
2. **"A2 분산 2.4배 → 재현성 훼손"** — n=3의 std 추정치끼리 비율 비교는 통계적으로 무의미 (std의 CI가 값 자체보다 큼). "관찰상 요동이 큼" 수준으로 강등해야.
3. **유의성 일반**: n=3 paired sign test의 최소 p=0.125 — **어떤 배치로도 p<0.05 불가능**. "유의" 단어 자체를 쓸 수 없음.

## ❌ 논리적으로 불가한 주장

1. **"3단계 모두 기여한다" / "제거하면 하락한다"** — full 부재로 어떤 arm도 하락 여부 판정 불가. A1이 이 프로토콜의 full보다 높을 가능성조차 배제 못 함.
2. **c1, c3 절대값** — 미식별.
3. **Table 8 병기·baseline 대비** — 프로토콜 상이.
4. **순위의 프로토콜 이전 가능성** — 가장 은밀한 함정. imgsz 256은 severstal 1600×256 스트립을 6.25:1로 뭉갬 — 결함이 수 픽셀로 축소. 이 해상도에서 위치 미세 신호(c3)는 억압되고 배경 전역 신호(c2)는 생존할 수 있음 → **c2≫c3 서열 자체가 프로토콜 산물일 가능성**. "상대 순위는 유효"라는 현재 문서 문구도 엄밀히는 "이 프로토콜 내에서 유효"로 한정해야 하며, 그룹 A 재실행이 순위 재현까지 확인해줘야 순위가 프로토콜-강건 사실이 됨.
