### 증거 — sympy 경고의 숫자가 범인을 지목한다

```
414  pow_by_natural([VR[2,  int_oo], VR[-1,-1]])
 90  pow_by_natural([VR[5,  int_oo], VR[-1,-1]])
 90  pow_by_natural([VR[3,  int_oo], VR[-1,-1]])
 54  pow_by_natural([VR[9,  int_oo], VR[-1,-1]])
 18  pow_by_natural([VR[17, int_oo], VR[-1,-1]])
```

`17 → 9 → 5 → 3 → 2` = **ceil(x/2) 하강 체인**. FPN 스트라이드 피라미드에서 공간 차원 하나가 전파된 것.

- `17 × 32 = 544`, `9 × 32 = 288`
- `imgsz=640` **정사각 letterbox면 640/32 = 20** → 20→10→5→3→2. **17·9가 나올 수 없다**
- 544·288은 stride 32 배수 → **ultralytics rect batch shape**

⇒ `--rect` 켜져 있고, 배치마다 shape이 바뀌었다. `[0/2]` = frame 0 **recompile 2회차**.

### 왜 mtd만 죽었나

MTD(Magnetic Tile Defect)는 **v2-1 5종 중 유일하게 이미지 크기가 제각각**이다. step5 로그의 normal 크기만 봐도:

```
218x273  196x317  585x253  609x240  126x285  360x364  531x312  514x340  292x323 ...
```

나머지는 고정 크기 — severstal 1600×256, leather 1024×1024, aitex 타일 256×256, kolektor 고정.

고정 크기 → rect가 **단일 batch shape** 산출 → 컴파일 1회, dynamic shape 없음 → 무사. mtd만 shape이 계속 갈리며 dynamo 재컴파일 → 동적 shape 경로에서 `AssertionError` 폭발.

타이밍도 맞는다: 희귀 shape이 처음 등장할 때 재컴파일 → 이미지 많은 random/aroma(816장)가 baseline(544장)보다 빨리 도달(84s vs 430s).

### 폴백이 못 잡는 이유

```python
if compile:
    train_kwargs["compile"] = True
try:
    return model.train(**train_kwargs)
except (SyntaxError, TypeError) as exc:      # ← AssertionError 미포함
    if "compile" in train_kwargs:
        train_kwargs.pop("compile", None)
        return model.train(**train_kwargs)
```

`SyntaxError`/`TypeError`만 잡는다. 이건 **구버전 ultralytics가 미지원 kwarg를 거부하는 경우** 대비용이다. 런타임 컴파일 실패는 설계상 통과 못 한다.

**③ 클래스 균형이 깨진다.** 앞서 확인 — severstal 이득은 Δsynth↔Δmap50 Spearman +0.95, 즉 **배분 효과**다. 전역 top-K로 뽑으면 점수 높은 클래스가 독식해 배분이 재왜곡되고, 지금 얻은 이득이 사라진다. 선별한다면 **반드시 클래스 내부(within-class) top-K**여야 한다.

### 함정 ① — 점수 분포가 계단형이다

quality의 50%가 **이진 항**이다: blur ∈ {0.3, 1.0}(계단), brightness ∈ {0.7, 1.0}(계단). 연속 항은 contrast·noise뿐. 분포가 매끈하지 않고 **덩어리(lump) 4개 + 내부 산포** 구조일 가능성이 높다. 분위 컷이 덩어리 내부에 떨어지면 동점(tie) 처리에 따라 거부율이 0% 또는 덩어리 통째로 튄다. 예: 한 데이터셋 타일 전부가 blur=0.3·brightness=0.7이면 실효 산포는 contrast+noise 40%뿐 — P15 경계가 촘촘한 동점대에 걸릴 수 있다. **로컬 분포 스캔으로 tie 구조 확인이 선결.**

### 함정 ② — void 게이트와 중복 축

분위 quality 게이트를 되살리면 "flat·edge-free" 축은 void 게이트(분산·엣지)와 겹친다. 순중복이면 게이트 2개가 같은 타일을 두 번 거른다. **단, brightness 항은 예외** — void 게이트가 원리적으로 못 잡는 **밝고 매끈한 이상(severstal 백색 침전물, 위험 5 사각)**을 quality의 brightness 항이 잡을 수 있다. 즉 분위 quality 게이트의 실질 가치 = void 게이트 사각 보완이고, 중복도 측정이 그 가치를 정량화한다.

### 적용 위치 3곳 — 수량 영향이 전혀 다르다

| 위치 | 거르는 것 | synth 수량 | parity |

### 논문이 실제로 주장하는 것 (확인)

§3.2.6: *"A quality gate filters unusable background patches… A patch is accepted as a usable clean background iff quality ≥ 0.7"* + §3.2.4의 score 기반 배치. **논문은 quality 게이트를 파이프라인의 일부로 명시 주장한다.** 그런데 frozen table을 만든 run에서 그 게이트는 fail-open no-op이었다 — 주장과 증거가 이미 어긋나 있다. 이 간극을 메우는 길은 둘뿐이었고:

## ③ 스터디 — ring_sgm 본체

### 선결 개념: 기하 3개

```
배경 이미지 (예: severstal 1600×256)
 → 64px 절단 격자 25×4 타일    (우/하단 나머지 = unobserved, 격자 밖)
 → void 타일 제외한 것이 grid  (①)

자리 s        = footprint(bw×bh 타일 사각형)를 놓을 좌상단 오프셋
footprint F(s) = 결함이 덮어쓸 타일들 — 합성 후 사라진다
ring R(s)     = 그 사각형의 8이웃 테두리 타일들 — 합성 후 살아남아 결함과 접한다
```

크기 사슬: 결함 bbox → fit-rescale 후 **effective (ew,eh)** → `bw=⌈ew/64⌉, bh=⌈eh/64⌉`. ②의 size_fit이 예고한 그 축소가 여기서 실좌표에 반영된다.

### 흐름 4단계 재확인

```
① admissibility: footprint 전 타일이 관측·비-void인 자리만 후보
② 후보 열거
③ (qf run) 자리 crop-영역 quality < P15 플로어 → 배제
④ 생존 자리 중 ∩(h_s, tgt[k]) argmax → 좌표 확정
```

### 심장 — 왜 이 목적함수인가 (§2)

**질문을 바꾼 것이 핵심이다:**

| | 구방식 (footprint 평균) | ring_sgm (분포 매칭) |
|---|---|---|
| 읽는 곳 | 결함이 **지울** 픽셀 | 합성 후 **남을** 둘레 |
| 계산 | 셀별 점수의 평균 | 히스토그램 교집합 |
| 실제로 고르는 것 | "점수 높은 셀이 많은 자리" = **데이터셋에서 가장 평범한 표면** | "둘레 구성이 실제 결함 주변 구성과 닮은 자리" |

평범-표면 수렴의 기전: `matrix_symmetric` 값은 양쪽 풀(결함 주변·clean)에서 **흔한 셀**일수록 높다. 평균은 그런 셀을 많이 가진 자리에 보상 → 흔함 자체가 목표가 돼버린다. 교집합은 **구성 비율**을 비교하므로 흔한 셀이 많아도 목표 분포보다 초과한 만큼은 기여하지 않는다(`min`이 자른다).

**증거가 교과서적이다 (§3-1b 기여 분리)** — 변인 하나씩 격리한 대조 arm:

```
footprint평균 → ring평균     : 악화 4/5  (severstal −0.270 → −0.502, 두 배 악화)
ring평균     → ring분포매칭  : 개선 5/5
```

ring은 footprint보다 타일이 **적어서** 흔한-셀 편향이 더 세게 먹는다 — 위치만 바꾸면 오히려 손해. **개선의 전부가 score 정의**다. 스터디에서 이 표 하나만 기억해도 ③의 절반이다.

### quality 필터가 얹히는 방식 (③단계)

## tgt[k] 생성 사슬 — 4단계

### 1단계 — 두 분포 세기 (phase0 프로파일링)

```
P_clean(c)   = 전체 good 이미지의 64px 배경 패치들이 셀 c에 떨어지는 비율
P_def(k, c)  = "군집 k 결함을 가진 이미지들"의 배경 패치 분포
```

핵심 디테일 2개:
- **패치가 이미지의 군집 라벨을 상속**한다 — 이미지에 군집 k 결함이 있으면 그 이미지의 배경 패치 전부가 P_def(k,·)에 기여
- **결함과 겹치는 패치는 제외** — P_def는 결함 자신이 아니라 **결함 둘레 배경**의 분포다 (그래서 ring과 비교 가능한 것)

### 2단계 — 스무딩 + 기하평균

```
양쪽에 ε = 10⁻³ 가산 스무딩
raw(k, c) = √( P_def(k,c) · P_clean(c) )
```

- **기하평균의 의미**: 두 조건의 AND — "군집 k 결함이 사는 문맥" **이면서** "clean 풀에 실존하는 표면". 한쪽이 0이면 0으로 붕괴 (스무딩이 그 절벽을 완화)
- 대칭: P_def와 P_clean을 동등하게 가중 — 이름 `matrix_symmetric`의 유래

### 3단계 — 행 max 정규화 → 저장 (`matrix_symmetric`)

```
matrix_symmetric[k][c] = raw(k,c) / max_c' raw(k,c')     ← 각 군집의 최적 셀 = 1
```

저장·해석용 (논문 Figure 3.2.4-1 히트맵이 이 형태 — "row-normalized so each cluster peaks at 1"). **확률분포가 아니다** — 합이 1이 아님.

### 4단계 — L1 재정규화 → tgt[k] (step3.5, `_target_by_cluster:525`)

```python
tgt[k][c] = matrix_symmetric[k][c] / Σ_c' matrix_symmetric[k][c']
```

- **왜 필요한가**: `∩(h_s, tgt)`는 분포끼리의 비교다. h_s는 합 1인데 상대가 max-정규화 값이면 교집합이 "겹친 질량"이라는 의미를 잃는다
- **왜 무해한가**: 스칼라 나눗셈(단조 rescale)이라 **행의 상대 형태 불변** — 어느 셀이 몇 배 중요한지는 그대로. 논문 수식 무수정 주장의 근거
- **지지집합의 침묵이 기능이다**: 행에 없는 셀(그 군집에서 미관측 조합)은 tgt에 **아예 없음** → 교집합 기여 0. 런타임 `_positive_place`의 `.get(cell, 0.5)` 중립 처리와 대비 — 미관측 셀에 0.5를 주는 편향이 여기선 자연 해소된다 (dev_note §2-1)

## k_fit ↔ R — 같은 과녁, 다른 사거리

### 구조: 같은 `tgt[k]`에 두 번 조준한다

```
                    tgt[k]  (군집 k의 목표 문맥 분포)
                    ↙                      ↘
1단계 k_fit = ∩(h_g, tgt[k])       2단계 ring = ∩(h_s, tgt[k])
h_g = 배경 이미지 전체의             h_s = 자리 s 둘레 6~20타일의
      비-void 타일 히스토그램              히스토그램
      (수백~수천 타일 집계)
"이 이미지에 그런 표면이            "정확히 이 자리 둘레가
 충분히 있는가" — 공급 확인           그런 표면인가" — 위치 특정
```

### 왜 2단이 필요한가 — 각자 못 하는 일이 있다

**ring 혼자는 안 되는 이유**: argmax는 랭킹이라 **절대 실패하지 않는다** — 나쁜 배경에서도 "그중 최선의 자리"를 반드시 내놓는다. 목표 셀이 아예 없는 이미지에서 ring argmax = 쓰레기 중 1등. **2단계는 1단계가 공급한 것 이상을 만들 수 없다.** k_fit이 천장을 정하고, ring이 그 천장 아래서 위치를 특정한다.

**k_fit 혼자는 안 되는 이유**: h_g는 이미지 전체 집계라 **"어디에"를 모른다.** 목표 혼합이 이미지 전역에 흩어져 있는 경우와 한 구역에 모여 있는 경우를 구분 못 한다. 결함 둘레라는 국소 구성은 ring만 잰다.

### 통계적 성격 차이 — 같은 수식, 다른 분산

| | h_g (1단계) | h_s (2단계) |
|---|---|---|
| 표본 | 수백~수천 타일 | **6~20타일** |
| 성격 | 안정적, 부드러운 분포 | 거칠고 노이지 — 타일 1개가 5~17%p를 움직임 |

그래서 1단계는 미세 차이까지 랭킹에 쓸 수 있지만, 2단계는 "구성이 대체로 닮았나" 수준의 매칭이다.

### 미묘한 지점 2개 (dev_note 근거)

**① P_clean 항의 정당성이 단계마다 다르다** (§2-2): tgt[k]에는 P_clean이 곱해져 있다. 1단계에서는 정당 — "clean 풀에 그런 표면이 실존하는가"가 배경을 고르는 시점의 유효한 질문. 2단계에서는 이미 이미지가 손에 있어 가용성 질문이 무의미해 보이는데, **그럼에도 유지**한다 — R4 실측에서 P_clean을 뺀 재정의(`ctx_local_lift`)가 개선을 못 냈고, 수식 무수정이 논문 기여 구조를 지키기 때문. "이론적으로 어색하나 실측이 유지를 지지"가 정직한 상태다.

**② 2단은 greedy지 joint 최적화가 아니다** (위험 8): 1단계가 이미지를 확정한 **뒤** 2단계가 그 안에서 argmax한다. k_fit이 낮아 버려진 이미지 안에 완벽한 자리 하나가 숨어 있어도 못 찾는다. 그리고 P1 검증은 배경을 무작위 30장으로 고정하고 자리만 쟀으므로 — **k_fit이 고른 배경 위에서의 ring 성능(상호작용)은 미측정**으로 남아 있다.

### 미니 예제로 연결

```

```
