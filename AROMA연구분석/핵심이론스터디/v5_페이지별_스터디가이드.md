### 15. 주변 밝기와 유효 ROI 탐색 (식 1 · 2)
- **학습 목표**: 두 식을 말로 풀어 설명할 수 있다
- **핵심 식** (졸업논문 식 (4-2)·(4-3), L435–448. 슬라이드의 "식 1·2"는 발표 번호)
  - **식 (4-2)** C_src = mean( I_def · (M_dilated − M_def) ) — 결함 둘레 고리의 평균 밝기.
    I_def는 결함이 있는 원본 그레이스케일 이미지(512×512). M_def는 그 결함 마스크(결함 픽셀 1, 나머지 0). M_dilated는 M_def를 원형 커널로 팽창시킨 마스크로, 결함보다 한 겹 더 넓은 영역을 1로 가진다. 두 마스크의 차 (M_dilated − M_def)는 팽창으로 새로 생긴 띠, 즉 결함을 둘러싼 **고리(ring)** 만 1로 남는 마스크다. 이 고리를 I_def에 곱하면 고리 픽셀의 밝기만 남고 나머지는 0이 되며, mean은 그 고리 픽셀들의 평균을 취한다(0이 된 바깥 픽셀은 평균 모집단에서 제외, 즉 고리 픽셀 수로 나눔 — 논문 본문 "고리 영역의 평균 휘도"). 결과 C_src는 스칼라 한 개로, "이 결함이 원래 어떤 밝기의 표면 위에 있었는가"를 요약한다. 결함 자체를 빼고 고리만 쓰는 이유는 결함 픽셀(어둡거나 밝은 이상값)이 배경 밝기 추정을 오염시키지 않게 하기 위함이다.
  - **식 (4-3)** Score_i = | C_src − C_tgt,i | — 후보 자리 i의 밝기 불일치 점수.
    정상 이미지 위를 128×128 창으로 32px 간격 슬라이딩하면 후보 패치 i가 여러 개 생긴다. C_tgt,i는 i번째 후보 패치의 평균 밝기(패치 전체 픽셀 평균)이고, Score_i는 그 값과 C_src의 절대 차이다. 0에 가까울수록 결함이 원래 놓여 있던 표면과 밝기가 비슷한 자리. 전 후보를 Score 오름차순으로 정렬해 상위 k개를 남기고, 그중 1개를 무작위로 뽑아 유효 ROI로 삼은 뒤 그 패치 중심에 생성 결함을 이식한다. top-1이 아닌 top-k 무작위인 이유는 같은 정상 이미지에서 매번 같은 자리가 선택되는 것을 막아 합성 위치 다양성을 확보하기 위함이다.
  - **두 식의 관계**: (4-2)는 결함 쪽에서 "기준값" 1개를 만들고, (4-3)은 정상 쪽 후보마다 그 기준값과의 거리를 잰다. 비교 대상이 둘 다 평균 밝기 스칼라 하나뿐이므로, 밝기는 같아도 줄무늬·얼룩처럼 텍스처가 다른 배경은 구분하지 못한다 — 이것이 슬라이드 19의 한계이자 제5장이 5개 텍스처 특징·분포 매칭으로 확장하는 출발점이다. 또한 결함 쪽은 **고리** 평균, 후보 쪽은 **패치 전체** 평균으로 비대칭인데, 제5장의 site_score는 양쪽 모두 ring 분포(h_s vs tgt[k])로 맞춰 이 비대칭을 없앤다.
- **프로젝트에서 확인할 것** (제4장 KolektorSDD 코드는 본 저장소(aroma)에 없음 — 별도 저장소에서 확인)

- **셀프 체크**
  - [ ] 왜 top-1이 아니라 top-k 중 무작위인가? (같은 위치 반복 방지, 다양성)

### 24. 배경 특징 셀 키와 CCI
- **학습 목표**: 패치 하나 → 셀 키, 데이터셋 전체 → CCI로 가는 두 단계를 설명할 수 있다
- **핵심 개념**
  - 셀 키: 5특징 각각을 P33/P66으로 0/1/2 → `2_2_1_2_0` 형식, 최대 243종, 호환성 행렬의 **열 c**

### 28. ctx_prior와 morph_prior
- **학습 목표**: 호환성 행렬의 한 칸이 무엇을 뜻하는지, 붉은 상자를 보고 설명할 수 있다
- **핵심 식** (졸업논문 식 (5-10), L636–640)
  - ctx_prior(k, c) ∝ √(P_def(k, c) · P_clean(c)), 행 최댓값 = 1
  - P_def(k, c) = 군집 k에 속한 결함 **이미지의 결함 아닌 패치 전부**(격자 전체 − 결함 과반 패치)에서 셀 c 비율. **ring 아님** — ring은 식 (5-16) h_s에서만 등장. P_clean(c) = 정상 이미지 전체 패치에서 셀 c 비율
  - morph_prior(k) = n_k / N
- **호환성 행렬 만드는 과정** (`scripts/distribution_profiling.py:551` `_build_symmetric`, 호출 `:953` `step6_compatibility_learning`)
  - 재료 3개 (데이터셋 1개 단위): ① `context_features.csv` — row 1개 = 64px 패치 1개, `image_id`(= `{defect_type}_{stem}`), `image_type`(good/defect), 5특징 raw. 결함 이미지는 결함 과반(>0.5) 패치가 이미 제외됨. ② `morphology_clusters.json`의 `cluster_assignments{image_id: k}` — 결함 mask 1장당 정수 k. ③ `bin_edges` — 5특징 각각의 P33/P66, 모집단 = context rows 전부(good+defect) (`_compute_bin_edges`).
  - 단계 (순수 카운트):

    | # | 동작 | 결과 |
    |---|---|---|
    | ① | 모든 row → `_context_cell_key` → 셀 코드 c (예 `2_2_1_2_0`) | row마다 c |
    | ② | `image_type == good` row만 셀별 세기 ÷ good 패치 총수 | P_clean(c) = `clean_dist` |
    | ③ | `image_type == defect` row → `image_id`로 k 조회 → (k, c) 세기 ÷ k의 패치 총수 | P_def(k, c) = `P_def_patch[k]` |
    | ④ | k마다, P_def(k, c) > 0인 셀(지지집합 S_k)만 raw = √((P_def + ε)(P_clean + ε)), ε = 1e-3 | 행 k raw |
    | ⑤ | 행마다 max로 나눔 → 최고 셀 1.0 | `matrix_symmetric[k][c]` |

  - 출력 `compatibility_matrix.json`: `matrix_symmetric`, `P_def_patch`, `clean_dist`, `bin_edges`, `symmetric_epsilon` + 구형 `matrix`.
  - 기하평균 + ε 이유: √(P_def · P_clean)은 결함 주변에도 흔하고(P_def↑) 정상 배경에도 흔한(P_clean↑) 셀만 높임. 한쪽만 높으면 √가 깎는다. ε = 0.001은 P_clean(c) = 0인 셀(결함 이미지에만 나오는 셀)을 0으로 죽이지 않고 √(P_def · 0.001)로 아주 작게 남겨 순위 바닥에 둔다. 지지집합 S_k 밖 셀(k 주변에 한 번도 안 나온 셀)은 행에 키 자체가 없음 = 0 취급.
  - 행 정규화 의미: 행 max = 1이라 행끼리 절대값 비교 불가. 행 안에서 "k가 선호하는 셀 순위"만 뜻한다. 그림 5-6 붉은 상자 = 행 argmax. tgt[k](식 5-16)는 이 행을 다시 합 1로 재정규화한 분포(`clean_bg_selection.py:525` `_target_by_cluster`).
  - 장난감 예 (셀 3개, k = 1):

    | c | P_def(1, c) | P_clean(c) | √곱 | ÷max |
    |---|---|---|---|---|
    | 2_2_1_2_0 | 0.50 | 0.10 | 0.224 | 0.53 |
    | 1_1_1_1_0 | 0.30 | 0.60 | 0.424 | **1.00** |
    | 0_0_0_0_2 | 0.20 | 0.00 | √(0.2 · 0.001) = 0.014 | 0.03 |

    결함 주변 최빈 셀(0.50)이 아니라 **양쪽 다 흔한 셀**(0.30 × 0.60)이 1위 — 기하평균 효과.
  - 군집 k = 행 번호 (슬라이드 26 연결): 결함 mask 1장 → 6특징 → GMM → k. 행렬은 mask 단위가 아니라 k 단위 행. 같은 k의 mask 전부가 행 k를 공유. 열 c = 243 셀 중 실제 관측 셀.
- **발표용 읽기 (2026-11-11 정리)**
  - 축: **행(y) = 결함 군집 k, 열(x) = 배경 셀 c**. 세 곳 일치 — 논문 그림 5-6 캡션 "각 행에서 붉은 상자", 플롯 코드 y눈금 `Cluster k`·x라벨 `Context Cell`(`distribution_profiling.py:1344`), JSON `matrix_symmetric[k][c]`.
  - 열 c의 정체: "clean image의 셀"이 아니라 **공통 셀 코드 체계**(P33/P66은 good+defect 전체로 1회 계산). 열에 실제로 있는 c = 지지집합 S_k(k 결함 이미지에서 관측된 셀)이고, clean 쪽은 값(√ 안의 P_clean)으로만 들어감. → "결함 이미지에서 관측된 c를 정상 이미지 빈도로 가중".
  - 무엇을 매칭하나: 결함 **형태** ↔ 배경 특징의 닮음이 아니라 **(k가 살던 배경 셀 분포) ↔ (정상 이미지 배경 셀 분포)의 공존 빈도**. 형태 벡터는 비교에 안 들어가고, k는 "어느 결함 그룹 기준으로 셀 것인가"의 행 인덱스일 뿐.
  - 붉은 상자 한 문장: "그 형태의 결함을 붙여 넣기에 가장 자연스러운 배경 종류 — 결함이 원래 살던 배경이면서 정상 이미지에서도 쉽게 찾을 수 있는 셀". P_def 단독 1등이 아니라 √(P_def·P_clean) 1등(위 장난감 예).
  - morph_prior[k] = n_k / N: k에 속한 결함 **개수의 비율**(0~1, Σ_k = 1). 배경·셀과 무관한 결함 쪽 스칼라. ctx_prior와 같은 [0,1] 스케일이라 그대로 더함. 역할 = **결함 간**(행 간) 비교. 행 안 순위는 ctx_prior만으로 결정.
  - **ROI_score의 단위는 mask가 아니라 (k, c) 쌍** = "결함 종류 × 배경 종류 조합의 우선순위표". 같은 k의 mask는 전부 동점(image-blind); 어느 mask 개체가 뽑히는지는 결정적 해시 타이브레이크(`roi_selection.py:626`). 실제 사진 g·픽셀 s는 29·30번 몫.
  - ROI_score 장난감 예 (결함 100개, K*=3, n_k = 50/30/20 → morph_prior 0.50/0.30/0.20):

    | k \ c | c_A | c_B | c_C |

    | 1 | 0.30 | 1.00 | 0.60 |
    | 2 | — | 0.50 | 1.00 |

    | (k, c) | ctx + morph | ROI_score | 순위 |

    | (1, c_B) | 1.00 + 0.30 | 1.30 | 2 |

    | (1, c_C) | 0.60 + 0.30 | 0.90 | 4 |
    | (2, c_B) | 0.50 + 0.20 | 0.70 | 6 |
    | (1, c_A) | 0.30 + 0.30 | 0.60 | 7 |

    k=1 행 안 순위(c_B > c_C > c_A)는 ctx_prior만으로; 행 사이에서는 흔한 k=0이 morph_prior로 따라잡음((0,c_B) = (1,c_C)). 드문 k=2가 0개 되는 건 클러스터별 기본 할당·클래스 하한 쿼터가 막음.

### 29. 결함과 배경 이미지 (식 3 · 5)
- **학습 목표**: 결함 선택과 배경 이미지 선택의 기준을 "셀 히스토그램 겹침" 한 개념으로 설명할 수 있다
- **발표 구조 (30초, 2026-11-11 정리)** — 식을 하나씩 읽지 않는다. 개념 → 연산 하나 → "무엇과 무엇을 겹치나" → 마무리.
  1. **목적 + 개념 한 줄**: "bg_score는 **결함이 없는 clean 이미지 중 어떤 이미지를 고를지** 판단하는 점수입니다. 결함 쪽 정보도 배경 쪽 정보도 전부 **배경 셀 히스토그램** 하나로 번역한 뒤, 겹치는 넓이로 점수를 매깁니다."
  2. **연산 하나만**: ∩(a, b) = Σ_c min(a(c), b(c)) — "두 막대그래프를 겹쳐 놓고 **겹친 면적**". 0(안 겹침)~1(완전 일치). 손짓으로 두 분포 겹치기.
  3. **식은 "무엇 ↔ 무엇"으로만**:

     | 적합도 | 비교 대상 (후보 clean 이미지 g ↔) | 한 마디 |
     |---|---|---|
     | src_fit | ROI 소스 이미지의 배경 분포 | "결함이 원래 포함된 표면과 닮았나" (결함 개별) |
     | class_fit | 클래스 집계 배경 분포 | "데이터셋의 결함 라벨 클래스의 결함들 표면과 닮았나" (클래스 집단) |
     | size_fit | fit-rescale 배율 | "해당 결함 mask 혹은 crop이 합성할 수 있을 정도로 이미지 사이즈가 충분한가" (기하 축, ∩ 아님) |

  4. **마무리**: "세 합이 최대인 정상 이미지를 고릅니다. 28번 ROI_score가 '어떤 결함을 **어떤 배경 종류**에'를 정했다면, bg_score는 '그 종류 중 **어느 사진**'입니다. 어느 **자리**는 30번."
- **슬라이드 구성 제안**: 상단에 개념 한 줄 → 가운데에 두 히스토그램이 겹치는 그림 1개(∩ 면적 음영) → 아래에 위 3행 표. 식 (5-11)~(5-15) 원문은 각주 크기로 내리고, 숫자(0.95 등)는 발표에서 읽지 않는다.
- **28 → 29 → 30 연결 한 줄**: 결함 종류 × 배경 종류(쌍) → 사진 g → 픽셀 s. 세 단계 모두 같은 ∩ 연산, 바뀌는 건 "무엇을 겹치나"뿐.
- **백업 (질문 받을 때만)** — 졸업논문 식 (5-9), (5-11)~(5-15)
  - ROI_score = ctx_prior + morph_prior (28번)
  - bg_score = src_fit + class_fit + size_fit, src_fit = ∩(h_g, p_src), class_fit = ∩(h_g, p_cls), size_fit = min(1, 0.95W/w, 0.95H/h)
  - **h_g** = 후보 정상 이미지 g의 셀 히스토그램 (g의 64px 패치 전부를 셀로 바꿔 센 비율). 세 적합도 중 둘이 이 h_g를 공통으로 쓴다.
  - **p_src** = 이 결함이 원래 있던 원본 이미지의 비결함 패치 셀 히스토그램(결함 개별 정보). 기본은 원본 이미지 전체, `--adjacent_radius`로 결함 인접 타일만 쓰는 국소화 옵션 있음(기본 OFF).
  - **p_cls** = 같은 결함 클래스 결함 이미지 전부의 비결함 패치를 합친 셀 히스토그램(클래스 집단 정보). src_fit이 한 장 표본이라 흔들릴 때 집단 평균으로 보정하는 축. 단일 클래스 데이터셋은 클래스 축이 없어 subtype 축으로 대체(`_roi_class_axis`).
  - **size_fit**: (W_g, H_g) = g 크기, (w, h) = 결함 크롭 크기. g가 크롭을 95% 여유로 담으면 1, 못 담으면 <1. 텍스처 아닌 기하 축 — 같은 크기 배경끼리는 상수.
  - 세 값 모두 0~1, 합이 bg_score. 논문은 단순 합(의도적 단순화). 코드 `clean_bg_selection.py:759`는 각 축의 판별력(ROI 내 best − median 평균)으로 데이터 유도 가중을 주고, 옵션 k_fit(∩(h_g, tgt[k])) 축을 더할 수 있음.
  - 한 셀에 몰빵해도 상대 분포가 그 셀에 적으면 ∩ 점수 못 얻음 → 분포 전체를 맞춰야 높음(평균 매칭 대비 장점).

  1. **목적 + 개념 한 줄**: "site_score는 **29번에서 고른 clean 이미지 안의 어느 픽셀 자리**에 결함을 놓을지 판단하는 점수입니다. 배경을 64px 타일 격자로 보고, 후보 자리마다 **둘레(ring) 타일의 셀 분포**를 만들어 '이 형태의 결함이 원래 앉던 배경 분포'와 겹칩니다."

- **학습 목표**: ROI 적합도 S와 표 6-2 호환성 행렬이 각각 무엇을 고르는지, 제5장 ctx_prior와 무엇이 다른지 식 없이 설명할 수 있다

  1. **목적 + 개념 한 줄**: "이 단계는 두 가지를 고릅니다. **어떤 결함 ROI를 템플릿으로 쓸지**(ROI 적합도 S), 그리고 **그 결함을 어떤 배경 유형 위에 놓을지**(표 6-2 호환성 행렬). 둘 다 배경을 5유형, 결함을 4유형으로 **라벨링한 뒤 규칙으로 점수**를 매깁니다."
  2. **연산 하나만**: 표 조회 + 가중 합. "결함 유형 행 × 배경 유형 열에서 값을 읽고, 연속성·안정성과 0.5/0.3/0.2로 더한다." 제5장의 ∩(분포 겹침)이 아니라 **라벨 간 룩업**.
  3. **"무엇 ↔ 무엇"**:

     | 항 | 비교 대상 | 한 마디 |
     |---|---|---|
     | S_matching (0.5) | 결함 subtype 행 ↔ 결함 중심이 놓인 배경 유형 열 (표 6-2) | "이 결함이 이 표면 위에 있는 게 자연스러운가" |
     | S_continuity (0.3) | ROI bbox가 덮는 64px 셀들의 배경 유형 | "ROI 안 배경이 한 종류로 이어지는가" |
     | S_stability (0.2) | 배경 분산·4분면 편차·엣지 밀도 | "배경이 평탄하고 고른가" |
     | 배경 선택 (3단계) | subtype 행의 점수를 가중치로 정상 배경 **이미지 1장** 가중 무작위 | "점수 높은 유형의 배경이 더 자주 뽑힌다" |

  4. **마무리 (제5장 대비)**: "제5장 ctx_prior는 **데이터에서 센 공존 빈도**(243 셀, 대칭 √)였고, 여기 표 6-2는 **설계자가 정한 규칙값**(5×4, 비대칭)입니다. 제6장은 그 대신 생성 단계(41·42번)에서 배경 문맥을 더 깊이 쓰는 쪽을 택했습니다. 선택 단위도 다릅니다 — 제5장은 사진 → 픽셀 자리까지, 제6장은 이미지 1장까지."

- **예상 질문 → 답**
  - "표 6-2 값은 어디서 왔나?" → 도메인 규칙(선형 긁힘은 줄무늬 결을 따르므로 stripe 1.0, 덩어리는 매끈한 면에서 가시성 최대 등). 데이터 카운트가 아님. 논문 "공존 확률 인코딩"은 값의 의도 설명.
  - "제5장 ctx_prior와 뭐가 다른가?" → 데이터 기반·대칭·243 셀 vs 규칙 기반·비대칭·5유형. 제5장은 자리까지, 제6장은 이미지까지.
  - "왜 이미지 안 위치는 안 고르나?" → 제6장은 생성 단계(3채널 힌트·프롬프트)가 배경 문맥을 흡수하므로 배치는 유형 수준으로 충분하다는 설계. 자리 선택의 정밀화는 제5장 AROMA의 기여.
  - "S ≥ 0.7이 61.3%라는 건?" → 템플릿 풀 비율. 0.5~0.7 acceptable, <0.5 제외.

  - 원칙 ① **결 정합(coherence)**: 결함의 기하가 배경의 구조 방향과 어울리는가. 선형 결함 ↔ 줄무늬.

     | 채널 | 재료 (40번 산출물) | 알려주는 것 |

  |---|---|
  | ControlNet | 새로운 결함 패치 생성 |
  | 호환성 행렬 | 생성된 결함을 붙일 정상 배경 선택 |
  | Poisson Blending | 결함 패치를 정상 배경에 합성 |

  한 줄: "ControlNet이 **그리고**, 호환성 행렬이 **배경을 고르고**, Poisson blending이 **붙인다**." 아래 ①②③이 이 세 역할의 세부.
- **단위**: 1단계 템플릿 풀의 결함 ROI 1개(= 원본 학습 이미지의 결함 bbox 주변 크롭, subtype·배경 유형·s·힌트·프롬프트 보유)가 출발점. 증강 = "이 ROI를 새 결함 이미지로 다시 그려서, 다른 정상 이미지에 붙이기".
- **① 생성** (`scripts/test_controlnet.py:344 generate_from_jsonl`): `train.jsonl`의 샘플(힌트 + 프롬프트)마다 ControlNet으로 512×512 결함 패치 생성. `--num_images_per_class '{"1":2,"2":10,...}'`로 클래스별 생성 수 차등 → 희소 Class 2에 많이 배정(247 → 519의 출처). seed = base + idx. 힌트·프롬프트는 **원본 ROI의 배경**에서 만든 것 → 생성 패치는 원본 표면 문맥을 따른다.
- **② 배경 선택** (40번 활용 2): subtype → 호환 유형 가중 + 밝기 ±30 필터 → train.csv에 없는 **정상 이미지(1600×256)** 1장.
- **③ 합성** (`scripts/compose_casda_images.py:768 _compose_single_task`, `src/preprocessing/poisson_blender.py`)
  - 마스크: 힌트 R채널에서 추출(`extract_mask_from_hint`, 임계 127). ControlNet 출력엔 마스크가 없으므로 조건으로 넣은 힌트가 곧 라벨.
  - 위치: **원본 ROI bbox 좌표 그대로** + x 방향 jitter(±100px, 기본) + 크기 scale(0.875~1.0 균등). 배경 안에서 위치 탐색은 하지 않음(제4장 슬라이딩·제5장 site_score와 다른 점). y는 고정. 경계 벗어나면 클리핑.
  - 블렌딩: 마스크 8px 타원 팽창 → `cv2.seamlessClone(NORMAL_CLONE)`, center = 붙일 bbox 중심. 옵션 smooth mask(21×21, σ 7) 기본 ON. 변형 수 `compositions_per_roi`(기본 1)로 같은 생성 패치를 다른 배경·jitter에 여러 번 붙일 수 있음.
  - 출력: 1600×256 합성 이미지 + 전체 크기 마스크 + YOLO bbox + metadata(suitability_score, subtype, 배경 유형, roi_bbox).
- **④ 품질 게이트** (`scripts/validate_augmented_quality.py:202`): Q = 0.20 blur + 0.20 artifact + 0.15 color + 0.25 defect_consistency + 0.20 presence, **Q ≥ 0.7** 통과. defect_consistency = 생성 마스크를 다시 subtype 분류해 조건과 같으면 1.0 / general 0.7 / 불일치 0.3. presence = 결함 면적비 0.1~30%면 1.0, 아니면 0.5. 통과율 83.0%(2,500 중 2,075).
  - 추가 pruning (`scripts/package_casda_data.py:555`): suitability ≥ 0.7 후 top-k 지정 시 클래스 비율 비례 할당(최소 1) → 클래스별 점수순 상위 quota → 잔여는 전체 점수순.
- **⑤ 통합** (`scripts/merge_datasets.py`): 통과 샘플 마스크 → RLE 인코딩 → 원본 train.csv와 합쳐 `train_augmented.csv`. 원본 5,237 + 합성 2,238 = 7,475 (42.7%).
- **한 줄 요약**: 원본 결함 ROI → (힌트·프롬프트) → ControlNet 재생성 → 호환 배경에 **원래 자리** 근처로 Poisson 합성 → Q ≥ 0.7 → RLE 통합. 다양성 출처 = 생성 노이즈(seed) + 배경 교체 + jitter/scale.
- **불일치 (코드 vs 논문)**: 논문 식 (6-18) Q = 0.3 Q_morph + 0.3 Q_sharp + 0.2 Q_artifact + 0.2 Q_area (4항). 코드는 5항 0.20/0.20/0.15/0.25/0.20 (color 항 추가, 비중 다름). 통과 기준 0.7·항목 의미(morph↔defect_consistency, area↔presence)는 대응. 별도 `score_casda_quality.py`(color 0.4/artifact 0.3/blur 0.3)는 백분위 pruning 참고용 — 논문의 Q 아님.
